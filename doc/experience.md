# 开发经验总结

## 一、环境配置问题

### 1. Windows PowerShell 执行策略问题

**问题描述**：执行 `.ps1` 脚本时提示 `PSSecurityException`，脚本被阻止运行。

**解决方案**：
- 使用 `.cmd` 批处理文件替代 PowerShell 脚本
- 或在命令前添加 `-ExecutionPolicy Bypass` 参数：
```powershell
powershell -ExecutionPolicy Bypass -Command "npm run dev"
```

**经验**：Windows 默认禁止执行未签名脚本，开发时优先使用批处理文件或显式指定执行策略。

---

### 2. npm 命令执行失败

**问题描述**：在 PowerShell 中直接运行 `npm` 命令失败。

**解决方案**：
- 使用完整路径或确保 Node.js 已添加到系统 PATH
- 使用 `npm.cmd` 替代 `npm`：
```powershell
npm.cmd install
```

**经验**：Windows 环境下优先使用 `.cmd` 版本命令，避免 PowerShell 别名冲突。

---

## 二、端口占用问题

### 3. 端口被占用

**问题描述**：启动服务时提示 `EADDRINUSE: address already in use`。

**解决方案**：
```powershell
# 查找占用端口的进程
netstat -ano | findstr :3001

# 杀死进程（替换 <PID> 为实际进程ID）
Stop-Process -Id <PID> -Force
```

**经验**：启动服务前检查端口占用，使用统一的端口管理策略。

---

## 三、跨域与代理问题

### 4. CORS 跨域错误

**问题描述**：前端请求后端 API 时出现 `Access-Control-Allow-Origin` 错误。

**解决方案**：
- 在后端配置 CORS 中间件（已在 Express 中配置）
- 使用 Vite 代理转发请求

**经验**：开发环境使用代理，生产环境配置正确的 CORS 策略。

### 5. Vite 代理不生效

**问题描述**：配置了代理但请求仍然失败。

**解决方案**：
- 检查 `vite.config.ts` 中 proxy 配置是否正确
- 确保代理路径匹配正确
- 重启前端开发服务器使配置生效

**经验**：修改 Vite 配置后必须重启服务器。

---

## 四、代码逻辑问题

### 6. process is not defined

**问题描述**：浏览器控制台报错 `ReferenceError: process is not defined`。

**解决方案**：
- Vite 项目中使用 `import.meta.env` 替代 `process.env`：
```typescript
// 错误
const value = process.env.VITE_APP_NAME

// 正确
const value = import.meta.env.VITE_APP_NAME
```

**经验**：Vite 在浏览器环境不支持 `process.env`，需使用 `import.meta.env`。

### 7. TypeScript 语法在 JS 文件中使用

**问题描述**：在 `.js` 文件中使用 TypeScript 类型注解导致语法错误。

**解决方案**：
- 将文件改为 `.ts` 或 `.tsx`
- 或移除类型注解，使用纯 JavaScript

**经验**：严格区分 JS 和 TS 文件，避免混用语法。

### 8. API 响应字段不匹配

**问题描述**：第三方 API 返回的字段与预期不符。

**解决方案**：
- 使用 `?.` 可选链操作符防止空值错误
- 在代码注释中记录解析的字段映射关系
- 添加错误处理，捕获字段不存在的情况

**经验**：对接第三方 API 时做好防御性编程，记录字段映射便于维护。

---

## 五、第三方 API 问题

### 9. 第三方 API 请求失败

**问题描述**：请求东方财富/同花顺 API 时超时或返回错误。

**解决方案**：
- 设置正确的 User-Agent 和 Referer 请求头
- 更换可用的 API 端点
- 添加重试机制和错误捕获

**经验**：第三方 API 可能随时变更，做好容错处理。

---

## 六、缓存问题

### 10. 缓存日志不显示

**问题描述**：缓存命中日志未在终端显示。

**解决方案**：
- 确保服务器进程在当前终端运行
- 检查日志输出逻辑是否正确
- 使用 `console.log` 替代其他日志方式

**经验**：开发时确保日志输出到当前终端便于调试。

---

## 七、样式问题

### 11. SVG 图标样式不美观

**问题描述**：火图标显示效果不佳。

**解决方案**：
- 使用渐变颜色替代单色填充
- 添加阴影效果增强立体感
- 实现动画效果提升视觉体验

**经验**：SVG 图标可通过 CSS 和 SVG 属性进行丰富的样式定制。

### 12. 移动端布局问题

**问题描述**：卡片间距在移动端显示不合理。

**解决方案**：
- 使用 CSS Grid 的响应式断点
- 根据屏幕尺寸调整间距大小
- 测试多种设备尺寸

**经验**：移动端优先，使用渐进增强策略。

---

## 八、测试与调试

### 13. 错误状态测试

**问题描述**：难以测试前端 error 卡片展示。

**解决方案**：
- 添加模拟失败的环境变量开关
- 创建测试脚本验证各种状态
- 在代码中预留调试入口

**经验**：开发时提前考虑测试需求，添加必要的测试开关。

---

## 九、构建问题

### 14. 前端构建失败

**问题描述**：`npm run build` 失败。

**解决方案**：
- 检查 TypeScript 类型错误
- 确保所有依赖安装完成
- 检查路径别名配置是否正确

**经验**：构建前运行 `tsc --noEmit` 检查类型错误。

---

## 十、最佳实践总结

1. **环境变量管理**：使用 `.env` 文件统一管理配置，区分开发和生产环境
2. **错误处理**：添加全局错误捕获，提供友好的错误提示
3. **日志记录**：关键流程添加日志，便于问题排查
4. **代码注释**：记录关键逻辑和第三方 API 字段映射
5. **防御性编程**：使用可选链、空值检查，避免崩溃
6. **响应式设计**：移动端优先，使用媒体查询适配不同屏幕
7. **测试开关**：添加开发模式下的测试入口和模拟数据
8. **文档更新**：及时更新 README 和技术文档

---

## 十一、常见问题速查

| 问题现象 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 页面打不开 | 服务未启动 | 启动前后端服务 |
| 请求返回 502 | 后端未运行或代理配置错误 | 检查后端状态和代理配置 |
| 数据不更新 | 缓存未过期 | 添加 `?refresh=1` 参数 |
| 控制台报错 | 代码语法错误 | 检查浏览器控制台错误信息 |
| 样式不生效 | CSS 文件未引入或路径错误 | 检查 import 路径 |
